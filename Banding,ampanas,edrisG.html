Module 1

Introduction & History

What is Computing?

Computing is the goal-oriented activity requiring, benefiting from, or creating computers. It encompasses theoretical algorithms, hardware design, software engineering, and processing data to solve problems and automate tasks efficiently.

Input & Processing

Receiving raw data and transforming it using algorithmic rules.

Storage & Retrieval

Preserving structured state across non-volatile or temporary media.

Output & Automation

Delivering actionable results to users or driving external systems.

History of Computing Milestones

Ancient Era

The Abacus

First mechanical counting device created for performing arithmetic operations quickly.

1830s

Babbage's Analytical Engine

Charles Babbage conceptualized the first mechanical general-purpose computer featuring ALU and memory concepts.

1940s

ENIAC & Vacuum Tubes

First-generation electronic digital computers using vacuum tubes for computation logic.

1950s - 1960s

Transistors & Integrated Circuits (ICs)

Replaced bulky vacuum tubes, dramatically increasing speed, reliability, and reducing computer size.

1970s - Present

Microprocessors & Cloud Era

Single-chip CPUs enabled Personal Computers (PCs), mobile computing, and globally distributed cloud platforms.

Paradigms & Environments

Modern Paradigms & Forms of Computing

Grid

Grid Computing

Combines heterogeneous computing resources across organizations to solve massive tasks.

Quantum

Quantum Computing

Utilizes qubits, superposition, and entanglement for exponential computing power in cryptography/simulations.

Ubiquitous

Ubiquitous / IoT

Seamless integration of smart computing objects into everyday environment and appliances.

Cloud

Cloud Computing

On-demand delivery of IT resources (servers, storage, DBs) over the internet with pay-as-you-go pricing.

Edge

Edge Computing

Processes data near the edge of the network (source) to minimize latency and bandwidth consumption.

Parallel Computing vs. Distributed Computing

Feature Parallel Computing Distributed Computing
Memory Architecture Shared memory / tightly coupled Distributed memory / loosely coupled
Physical Location Single computer / multi-core CPU Multiple networked autonomous systems
Communication High-speed bus or shared RAM Network protocols (TCP/IP, HTTP)
Primary Goal Increase raw processing speed Resource sharing & fault tolerance

Types of Computing Environments

Personal Environment

Single-user standalone computer (laptop/desktop) executing localized application software.

Time-Sharing Environment

Multiple users share mainframe CPU time concurrently via rapid CPU multiplexing.

Client-Server Environment

Clients request resources/services; centralized servers process and return responses.

Peer-to-Peer (P2P)

Decentralized network where all nodes act as both clients and servers equally.

Databases & Core SQL Data Types

A Database is an organized collection of structured information stored electronically in a computer system managed by a DBMS.

Numeric Data Types
  • INT / INTEGER: Whole numbers (-2147483648 to 2147483647).
  • FLOAT / DOUBLE: Floating point decimal values.
  • DECIMAL(M,D): Exact monetary fixed-point numbers.
String / Character Types
  • VARCHAR(n): Variable length string up to n characters.
  • CHAR(n): Fixed-length character string.
  • TEXT: Large text string for long descriptions.

Essential MySQL Command Cheat Sheet

Data Definition Language (DDL) 
-- Create Database & Table
CREATE DATABASE school_db;
CREATE TABLE Students (
    student_id INT PRIMARY KEY AUTO_INCREMENT,
    first_name VARCHAR(50) NOT NULL,
    gpa DECIMAL(3,2)
);

-- Alter Table Structure
ALTER TABLE Students ADD email VARCHAR(100);

-- Drop Table
DROP TABLE Students;
Data Manipulation Language (DML) 
-- Select Query
SELECT first_name, gpa FROM Students WHERE gpa >= 3.5 ORDER BY gpa DESC;

-- Insert Row
INSERT INTO Students (first_name, gpa) VALUES ('Alice', 3.85);

-- Update Row
UPDATE Students SET gpa = 3.90 WHERE student_id = 1;

-- Delete Row
DELETE FROM Students WHERE student_id = 1;

Entity-Relationship (ER) Modeling

Entity Classification & Kinds

An Entity is a real-world object or concept about which data is stored.

Two Primary Entity Types

  • Strong Entity: Can exist independently of other entities. Has a primary key (e.g., Student).
  • Weak Entity: Depends on a strong entity for existence. Uses a partial key + owner key (e.g., Dependent of an Employee).

Kinds of Entities

  • Tangible: Physical entities (e.g., Car, Building, Employee).
  • Intangible: Conceptual entities (e.g., Account, Course, Order).
  • Associative Entity: Link table mapping M:N relationships into 1:M relationships.

Types of Attributes

Simple / Atomic

Cannot be divided further (e.g., Age, Gender).

Composite

Can be split into sub-parts (e.g., Full Name → First, Last).

Single-Valued

Holds exactly one value for an entity (e.g., SSN).

Multi-Valued

Can store multiple values (e.g., Phone numbers, Skills).

Derived

Calculated from another attribute (e.g., Age derived from Birthdate).

Key Attribute

Uniquely identifies an entity instance (e.g., Student_ID).

Degree of Relationship Set

The degree refers to the number of participating entity sets involved in a relationship.

Unary (1)

Recursive Relationship

Single entity associated with itself (e.g., Employee manages Employee).

Binary (2)

Two Entities

Most common; links 2 entity types (e.g., Student enrolls in Course).

Ternary (3)

Three Entities

Involves 3 entities simultaneously (e.g., Doctor, Patient, Medicine).

N-ary (N)

N Entities

Generalization involving N entity sets in a complex structure.

Hardware Architecture & Memory

What is a CPU?

The Central Processing Unit (CPU) is the "brain" of the computer responsible for executing program instructions through fetch-decode-execute cycles.

ALU

Arithmetic Logic Unit: Performs mathematical (+,-) and logical comparison calculations.

Control Unit (CU)

Directs operation timing, fetches instructions, and manages data flow across buses.

Registers

Ultra-fast internal CPU storage locations for immediate operands and instructions.

Clock Speed

Measured in GHz; determines how many execution cycles CPU performs per second.

Computer Memory Hierarchy

RAM (Random Access Memory) - Volatile

Stores active data and running application instructions temporarily while power is on.

SRAM: Fast, costly, flip-flop memory used for CPU Cache.
DRAM: Uses capacitors needing periodic refresh; used for main memory.

ROM (Read Only Memory) - Non-Volatile

Contains persistent bootup instructions (BIOS/UEFI firmware).

PROM: Programmable once EPROM: Erasable via UV Light EEPROM: Electrically Erasable Flash

Non-Volatile Storage Devices

  • HDD (Hard Disk Drive): Magnetic spinning platters with mechanical read/write heads.
  • SSD (Solid State Drive): High-speed NAND flash memory without moving parts.
  • Flash Drives / SD Cards: Portable semiconductor non-volatile memory.
  • Optical Storage: CDs, DVDs, and Blu-ray disks read via laser optics.

Magnetic Tape Storage

Magnetic Tape is a legacy non-volatile secondary storage medium using sequential data access. While slow for random reads, modern LTO (Linear Tape-Open) tape formats remain widely used today for low-cost, high-capacity enterprise data archiving and offline backup preservation.

Computer Hardware Ports & Interfaces

USB (Type A/C)

Universal serial connection for peripherals & power.

HDMI / DisplayPort

High-definition audio and video transmission output.

Ethernet (RJ-45)

Wired local area network (LAN) data connection.

Thunderbolt

Ultra-high bandwidth interface for PCIe & displays.

Languages, Data Comm & Society

Computer Languages Hierarchy

Low-Level Languages

Directly execution-compatible with CPU hardware architecture.

  • Machine Language: Binary code (0s and 1s) directly executed by CPU.
  • Assembly Language: Uses mnemonic codes (e.g., MOV, ADD) requiring an Assembler.
High-Level Languages

Human-readable abstractions independent of specific hardware.

  • Compiled Languages: C, C++, Rust (translated all at once via Compiler).
  • Interpreted Languages: Python, JavaScript (translated line-by-line via Interpreter).

Data Transmission Modes

Simplex Mode

Unidirectional flow. Data travels in only one direction.

Example: Keyboard → CPU, Radio Broadcasting.
Half-Duplex Mode

Bidirectional flow, but only one direction at a time.

Example: Walkie-Talkies.
Full-Duplex Mode

Simultaneous bidirectional flow in both directions at once.

Example: Mobile Telephone Calls.
